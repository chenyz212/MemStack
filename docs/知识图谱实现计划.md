# 圆形 Obsidian 记忆图谱实施计划

## 目标与边界

在当前 Rust + Tauri + Vue 3 架构内实现真实记忆图谱、检索联动和总览记忆中枢。

图谱工作区继续使用原型中的矩形 Canvas，但节点整体必须形成以画布中心为圆心的圆形 Obsidian 关系云，不允许出现横向拉长、项目分散成多个团块或边界参差的不规则形状。

只修改新桌面端；不修改旧 Java、WPF/.NET 代码。取消所有 MCP 粒子和连接脉冲动画。

## 数据与关系

- 直接复用现有 `memory_edge` 表，不生成随机节点或模拟连线。
- 每个节点只代表一条正式记忆；项目只负责颜色和筛选，不形成项目、标签或人物节点。
- 节点包含标题、摘要、标签、作用域、项目信息、记忆类型、重要度、收藏、置顶和更新时间。
- 归档记忆及已归档项目中的记忆不进入图谱。
- 关键词分使用标准化后的 `keywords + tags` 集合计算 Jaccard 相似度。
- 有向量时：`语义 × 0.60 + 关键词标签 × 0.30 + 同项目 × 0.10`。
- 无向量时：`关键词标签 × 0.80 + 同项目 × 0.20`。
- 语义分达到 `0.72` 或关键词标签分达到 `0.50` 才能成为候选关系。
- 同项目只能增强已有关系，不能单独产生连线；个人记忆之间不计算同项目加权。
- 每个节点最多保留 8 条最强关系，两个记忆 ID 固定排序后保存。
- 关系原因使用 `SEMANTIC`、`KEYWORD`、`MIXED`，前端展示中文原因和百分比分数。

## 圆形布局算法

- 使用 `d3-force` 处理连线、斥力和碰撞，使用 `d3-quadtree` 完成节点命中检测。
- 初始坐标使用确定性的黄金角圆盘分布，而不是随机坐标：角度按黄金角递增，半径按 `sqrt(index / count)` 分布。
- 重要度高、置顶、收藏和连接数高的节点优先排在圆心附近；普通节点逐渐向外分布。
- 局部图谱把中心记忆固定在 `(0, 0)`；全局图谱只固定整体质心，不强行指定中心记忆。
- 图谱半径固定为 `画布宽高较小值 × 0.42`，始终使用同一 X/Y 比例，禁止把圆形布局拉伸成椭圆。
- 增加自定义圆形边界力：节点接近半径边界时产生渐进向心力，越界后按圆周法线拉回。
- 节点拖动也必须限制在圆形边界内，不能再使用独立的矩形 `minX/maxX/minY/maxY` 截断。
- 项目不使用横向偏移或独立聚类中心，避免多个项目把整体轮廓拉成不规则形状。
- 力模拟稳定后立即停止；筛选、拖动或切换局部中心时短暂重新升温，稳定后再次停止。
- 缩放和平移只改变观察视口，不改变圆形节点云本身。
- “适应窗口”根据圆形包围半径居中缩放，保证整个圆形关系云完整可见。
- 总览的 24 节点预览复用同一圆形布局规则，不能使用当前装饰性星图。

## 后台关系计算

- 将现有 Embedding Worker 收敛为通用后台任务 Worker。
- 显式支持 `EMBED_MEMORY`、`REBUILD_EMBEDDING`、`REBUILD_GRAPH_MEMORY`、`REBUILD_GRAPH_ALL`。
- 创建、更新、恢复记忆后排入单记忆关系重算；Embedding 成功后再次重算该记忆。
- 归档时立即删除相关边；永久删除继续使用外键级联。
- 关闭云端处理后删除向量和纯语义关系，再按关键词重新计算。
- 全量重建按置顶、重要度和最近更新时间排队，不阻塞 MCP 或界面。
- 图谱响应返回 `READY` 或 `BUILDING`；构建期间允许展示已经生成的节点和关系。

## 接口与类型

| 接口                          | 用途                         |
| ----------------------------- | ---------------------------- |
| `GET /api/graph/global`       | 获取全局圆形图谱             |
| `GET /api/graph/neighborhood` | 获取指定记忆的一跳或两跳邻域 |
| `POST /api/graph/rebuild`     | 排队执行全量关系重建         |

- 查询显式传入项目集合、是否包含个人记忆、时间范围、`limit=120` 和 `minScore=0.45`。
- 后端强制 `limit <= 300`、`depth <= 2`、分数范围为 `0..1`。
- 新增 `GraphNode`、`GraphEdge`、`GraphResult`、`GraphGlobalQuery`、`GraphNeighborhoodQuery`。
- 返回 `nodes`、`edges`、中心记忆、截断状态、构建状态和真实节点/关系数量。
- Tauri Command 保持薄层，所有关系计算放在独立 `GraphService`。

## 图谱界面

- 新建独立图谱视图组件和 Canvas 交互组合函数，避免继续扩大单体 `App.vue`。
- 严格保留原型的标题区、全局/局部切换、点阵背景、中央搜索、筛选面板、节点详情、底部工具栏、项目图例和相关记忆入口。
- 左侧导航进入时默认显示全局圆形图谱。
- 从记忆详情进入时直接显示以该记忆为圆心的两跳局部图谱。
- 单击节点打开详情；双击打开完整记忆；局部模式始终把选中节点移动到圆心。
- “显示关系箭头”改为“显示关系分数”，因为当前关系是无向相似关系。
- 项目筛选只隐藏或显示节点，不重新建立多个项目聚类中心。
- 支持关系强度、最近 7 天、最近 30 天和不限时间筛选。
- 支持滚轮缩放、空白处平移、节点拖动、放大、缩小、适应窗口和 `Ctrl+F` 搜索。
- Canvas DPR 上限为 2；窗口隐藏时停止计算；减少动画模式下直接计算最终布局。
- 提供加载、空图谱、关系构建中、失败重试、搜索无结果和数据截断状态。
- 浅色、深色、窄桌面和移动尺寸均保持圆形节点云，不因响应式布局变成椭圆。

## 总览记忆中枢

- 保留当前总览结构、主文案和右侧快速记录卡，只改造左上记忆核心和活动文案。
- 中心显示真实有效记忆数量。
- 最多 6 个未吊销、未过期的 AI 工具按最近使用顺序分布在双层轨道，其余显示静态 `+N`。
- 工具名称、字母和颜色复用现有 MCP 客户端目录。
- 环绕动画只使用合成层 CSS `transform`；窗口隐藏、离开总览和减少动画模式下停止。
- 不实现粒子、光点汇入、连接脉冲或循环调用演示。
- 总览下方图谱预览改为真实的圆形 24 节点 Canvas，点击进入全局图谱。

## MCP 活动文案

- SQLite schema 升级到 v8，在 `mcp_token` 增加最近记忆动作、作用域和时间字段。
- 仅成功执行五个读取工具及 `memory_create` 后记录活动。
- 更新、归档、候选提交、失败调用和权限拒绝不记录为读取或创建。
- 作用域支持 `Personal`、`Project`、`Mixed`。
- 混合读取显示“Codex 刚刚读取了项目与个人记忆”。
- 单一范围显示“Claude 3 分钟前创建了个人记忆”等文案。
- 不显示项目名称、记忆标题或正文。
- 复用现有每秒 `PRAGMA data_version` 探测刷新总览，不新增 SSE 或高频全量请求。

## 检索联动

- 关键词和语义召回后，对强结果扩展一跳 `memory_edge`。
- 有语义时使用关键词 50%、语义 35%、图谱 10%、元数据 5%。
- 无语义时使用关键词 85%、图谱 10%、元数据 5%。
- 图谱召回增加 `GRAPH` 匹配原因，但不能覆盖标题精确匹配。
- 项目范围 Token 不得通过图谱扩展到其他项目。
- `memory_context` 继续遵守字符预算、去重和 MMR，不调用文本模型总结。

## 测试与验收

- 测试 schema v7→v8、关系公式、关系阈值、同项目不单独连线、每节点最多 8 条边。
- 测试创建、更新、Embedding、归档、恢复和全量重建的增量关系维护。
- 测试全局/局部、一跳/两跳、项目筛选、时间筛选、120/300 节点限制。
- 测试 MCP 成功读取和创建活动、混合作用域、空结果、失败不记录及权限隔离。
- 测试图谱 10% 检索权重、标题精确匹配优先和跨项目禁止扩展。
- 布局单测要求 95% 节点位于目标圆形半径内，所有节点不得越过圆形硬边界。
- 稳定布局的 X/Y 跨度比必须在 `0.90–1.10`，超过范围即判定为被拉成长条或椭圆。
- 120 节点初次绘制目标小于 500ms；300 节点拖动和缩放维持 45–60 FPS。
- 使用浅色/深色的 `1440×900`、窄桌面和 `390×844` 截图检查圆形轮廓、居中、文字遮挡和面板越界。
- 执行 `cargo test --workspace`、Rust 格式与静态检查、`npm test`、`npm run typecheck`、`npm run build`。
- 最终验收以“矩形工作区中呈现稳定、居中、近圆形的 Obsidian 节点云”为硬性视觉标准，不接受当前不规则轮廓。
