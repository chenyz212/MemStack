# 忆栈故障排查手册

> 适用版本：0.4.0（Rust/Tauri 版）
> 日志目录：`%LOCALAPPDATA%\UnifiedAiMemory\logs\`

## 一、日志与诊断文件

| 文件 | 内容 |
|---|---|
| `startup-error.log` | 启动失败中文摘要（含 UTC 时间戳；启动成功后自动清理） |
| `mcp-stdio.log` | MCP stdio 进程启动/认证/退出记录（不含令牌明文） |
| `database-migration.log` | schema 迁移步骤记录 |
| `desktop.log` / `embedding-worker.log` | 预留（对应模块启用后写入） |

日志自动治理：单文件超 5MB 轮换为 `.1`（仅保留一代）；logs 目录总占用超 50MB 按最旧删除非当前文件。

## 二、启动失败（弹窗 + startup-error.log）

### 1. 「创建首次运行备份失败」

| 原因 | 处置 |
|---|---|
| 磁盘空间不足 | 清理磁盘（备份需要约等于数据库大小的空间） |
| 备份目录被占用/只读 | 关闭占用 `%LOCALAPPDATA%\UnifiedAiMemory\backup` 的程序 |
| 上次备份残留损坏 | 删除 backup 目录内 `pre-rust-*` 残留文件后重启（marker 未写，会自动重试） |

### 2. 「打开数据库失败」

| 原因 | 处置 |
|---|---|
| 数据库文件被其他程序锁定 | 关闭 C# 旧版/其他忆栈实例（任务管理器搜「统一AI记忆」「memstack」） |
| 文件损坏 | 用 `backup\pre-rust-*.db` 恢复（见《用户升级说明》第六节） |
| 磁盘满 | 清理后重试 |

### 3. 弹窗提示 WebView2

未安装 Microsoft Edge WebView2 Runtime：从微软官网安装「Evergreen Standalone x64」后重启忆栈。

## 三、MCP 连接问题

### 客户端显示 MCP 连接失败 / 工具不可用

1. 忆栈「连接你的 AI」→ 对应卡片「编辑」→ **连接测试**：
   - 测试通过但客户端连不上 → 重启 AI 客户端（多数为配置缓存）；
   - 测试失败并提示「未找到 MemStack-MCP.exe」→ 确认 `MemStack-MCP.exe` 与 `忆栈.exe` 在同一目录（绿色版），或通过页面重新写入配置。
2. 黄色警示「程序位置已变化」→ 点**一键重新注册**（绿色版移动目录后的正常现象）。
3. `mcp-stdio.log` 出现「UNIFIED_AI_MEMORY_TOKEN 无效或已过期」→ 令牌已吊销/过期：页面重新生成或在客户端移除旧环境变量，改用会话 ID 接入。
4. 多客户端并发时数据库 BUSY：属异常，正常有 5 秒锁等待；持续出现请保留 `mcp-stdio.log` 反馈。

### stdio 输出被污染排查

MCP stdout 只允许协议帧；若客户端解析失败且日志无异常，检查是否手动给 exe 加过输出重定向/包装脚本。

## 四、数据问题

### 检索结果缺失 / FTS 报错

- 启动时自动校验 FTS5 编译开关，缺失会直接启动失败（ bundled SQLite 恒启用，正常不会出现）；
- 中文检索异常：确认搜索词无特殊符号；必要时「设置 → Embedding」重建向量。

### 怀疑数据不一致

1. 退出所有忆栈进程。
2. 对比 `data\memory.db` 与 `backup\pre-rust-*.db`（`.sha256` 可校验备份完整性）。
3. 按《用户升级说明》第六节回滚流程处理。

## 五、桌面行为问题

| 现象 | 处置 |
|---|---|
| 点击 exe 无窗口 | 已有实例在托盘：单击托盘图标恢复；或任务管理器结束 memstack-desktop 后重启 |
| 关闭窗口后"退出"了 | 设计为关闭到托盘；彻底退出请用托盘右键「退出」 |
| 窗口位置错乱 | 删除 `%LOCALAPPDATA%\UnifiedAiMemory\window-state.json` 后重启 |
| 卸载后数据仍在 | 设计如此：卸载不删除 `%LOCALAPPDATA%\UnifiedAiMemory`；需要彻底清理时手动删除该目录 |

## 六、回滚到 C# 版

完整步骤见《用户升级说明-0.4.0》第六节。要点：schema 未变化，通常直接换回 C# 0.4.0 即可；数据校验异常时用 pre-rust 备份恢复。
