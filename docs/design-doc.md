# MemStack 关系图谱功能设计文档 (V2)

## 1. 概述 (Overview)

### 1.1. 背景与目标
MemStack 旨在提供一个轻量级的本地知识管理系统。为了可视化地展示记忆（Memory）之间的关联关系，我们需要实现一个高性能、高可扩展性的关系图谱（Knowledge Graph）组件。

**核心目标：**
- **Obsidian 风格体验**：提供类似 Obsidian 的自由、流畅的节点拖拽与布局体验，采用浅色主题，视觉清爽。
- **高性能渲染**：支持 500+ 节点流畅交互（60 FPS），解决目前 SVG 渲染和物理引擎性能瓶颈。
- **搜索驱动视图**：图谱不再是孤立的展示工具，而是搜索结果的可视化延伸——搜索时自动展示“搜索词相关记忆 + 语义邻居”。
- **动态视图模式**：支持默认视图（核心记忆）、搜索视图、项目视图、局部视图的无缝切换。

### 1.2. 术语定义
- **Node (节点)**：图谱中的一个点，代表一条记忆（Memory）。
- **Edge (连线)**：两个节点之间的关系，由语义相似度、关键词重叠度等信号生成。
- **Force-Directed Layout (力导向布局)**：基于物理力学模拟的自动布局算法。
- **Spatial Grid (空间网格)**：一种用于加速空间查询（如斥力计算）的数据结构。

## 2. 需求分析 (Requirements)

### 2.1. 功能性需求
1.  **图谱视图模式**：
    -   **默认视图**：展示 Top 500 核心记忆（按重要度、收藏、连接数等综合排序）。
    -   **搜索视图**：输入搜索词后，实时切换为“搜索结果 + 1-2 跳语义邻居”的子图谱。
    -   **项目视图**：按项目筛选，展示特定项目内的记忆网络。
    -   **局部视图**：以选中的单个节点为中心，展示其周围 1-2 跳的邻居网络。
2.  **交互操作**：
    -   **拖拽**：支持节点自由拖拽，无圆形边界限制。
    -   **缩放与平移**：支持画布整体缩放和拖拽平移。
    -   **悬停/聚焦**：鼠标悬停节点时，高亮其直接连线和邻居，并显示 Tooltip（节点标题）。
    -   **标签显示**：默认隐藏所有节点标签，仅在悬停、选中或特定操作时显示。
3.  **视觉表现**：
    -   **浅色主题**：默认采用浅色背景。
    -   **节点样式**：小而紧凑（半径 3~5px），根据项目或记忆类型上色。
    -   **连线样式**：细腻（宽度 0.5~1.2px），可根据关系类型（语义/关键词）区分颜色。

### 2.2. 非功能性需求
- **性能指标**：在 500 节点规模下，拖拽操作帧率 ≥ 55 FPS；搜索视图切换响应时间 < 500ms。
- **可扩展性**：后端图谱查询需支持分页或分批加载，以应对万级数据量。
- **兼容性**：保留现有接口，平滑升级。

## 3. 系统设计 (System Design)

### 3.1. 架构设计
采用 **前后端分离** 架构：
-   **后端 (Rust)**：负责数据聚合、关系计算、排序截断。提供统一的图谱数据查询 API。
-   **前端 (Vue 3 + Canvas)**：负责 UI 渲染、物理模拟（布局算法）、交互事件处理。

### 3.2. 模块划分
-   **后端模块**：
    -   `GraphService`: 核心逻辑，实现 `get_graph_data` 接口。
    -   `SearchEngine`: 用于支持搜索视图的混合检索（FTS5 + 向量）。
-   **前端模块**：
    -   `GraphCanvas.vue`: 主画布组件，挂载 Canvas 元素。
    -   `renderer.ts`: Canvas 渲染逻辑（节点、连线、光晕、动画）。
    -   `physics.ts`: 物理引擎（力导向计算、空间网格加速）。
    -   `layout.ts`: 布局初始化算法（正态分布、圆形分布等）。

## 4. 详细设计 (Detailed Design)

### 4.1. 数据模型
#### 4.1.1. 图谱传输结构 (GraphNode)
```typescript
interface GraphNode {
  id: string;
  title: string;
  projectId: string | null;
  projectName: string | null;
  importance: number;
  degree: number; // 连接数
  isFavorite: boolean;
  // 运行时状态
  x: number;
  y: number;
  vx: number;
  vy: number;
  fx?: number | null; // 固定位置（拖拽时）
  fy?: number | null;
  // 视图元数据
  viewScore?: number; // 用于默认视图排序
  isAnchor?: boolean; // 搜索视图中的锚点
}
```

#### 4.1.2. 连线结构 (GraphEdge)
```typescript
interface GraphEdge {
  source: string; // Node ID
  target: string; // Node ID
  score: number; // 关系强度 [0, 1]
  type: 'SEMANTIC' | 'KEYWORD' | 'TAG' | 'CO_OCCURRENCE';
}
```

### 4.2. 后端 API 设计
#### 4.2.1. 统一查询接口
用于获取图谱数据，支持多种视图模式。

-   **Endpoint**: `POST /api/graph/query`
-   **Request Body**:
```json
{
  "mode": "default" | "search" | "project" | "local",
  "params": {
    "query": "搜索词", // mode=search 时必填
    "projectId": "uuid", // mode=project 时必填
    "centerNodeId": "uuid", // mode=local 时必填
    "depth": 2, // 邻居扩展深度，默认 2
    "limit": 500, // 最大节点数，硬上限 500
    "minScore": 0.3 // 连线最低分
  }
}
```
-   **Response**:
```json
{
  "nodes": [/* GraphNode[] */],
  "edges": [/* GraphEdge[] */],
  "truncated": false, // 是否被截断
  "totalAvailable": 1200 // 符合条件的总节点数
}
```

### 4.3. 前端物理引擎设计 (性能核心)

#### 4.3.1. 力导向布局算法
采用经典的力导向模型（类似 d3-force），包含以下力：
-   **Repulsion Force (斥力)**: 所有节点相互排斥，防止重叠。
-   **Link Force (连线力)**: 连接的节点相互吸引，保持理想距离。
-   **Center Force (向心力)**: 弱力，防止节点无限发散。

#### 4.3.2. 空间网格加速 (Spatial Grid)
**问题**：标准斥力计算复杂度为 O(N²)，500 节点即需计算 25 万次，导致卡顿。
**方案**：引入空间网格。
-   将画布划分为 40px x 40px 的网格。
-   每个节点归入一个格子。
-   计算斥力时，仅需计算 **自身格子 + 周围 8 个格子** 内的节点。
-   **效果**：复杂度从 O(N²) 降至 O(N * K)，其中 K 为局部邻居数，极大提升性能。

#### 4.3.3. 无边界约束
-   移除原有的硬边界（圆形边界）。
-   使用弱向心力 (`gravity: 0.01`) 确保节点不会因为斥力而飞离屏幕太远。
-   支持画布无限平移。

### 4.4. 视觉与交互设计 (UI/UX)

#### 4.4.1. 主题配色 (浅色模式)
| 元素 | 颜色值 | 说明 |
|---|---|---|
| **Background** | `#F7F7F8` | 画布背景 |
| **Node (Default)** | `#94A3B8` (灰) | 默认节点颜色 |
| **Node (Project)** | `#3B82F6` (蓝) | 项目关联节点 |
| **Node (Anchor)** | `#F59E0B` (金) | 搜索锚点节点 |
| **Edge** | `#CBD5E1` | 默认连线 |
| **Edge (Hover)** | `#64748B` | 聚焦连线 |
| **Text** | `#1E293B` | 标签文字 |

#### 4.4.2. 交互逻辑
-   **Hover (悬停)**：
    1.  计算鼠标位置所在节点（Hit Test）。
    2.  高亮该节点及其 1 跳邻居节点。
    3.  高亮与该节点相关的连线（加粗、变暗其他连线）。
    4.  显示 Tooltip (节点标题)。
-   **Drag (拖拽)**：
    1.  按下节点，设置 `fx/fy` 固定坐标。
    2.  移动鼠标，实时更新固定坐标。
    3.  物理引擎继续运行，邻居节点会随之调整。
    4.  松开鼠标，取消固定，节点自然漂浮。
-   **Search (搜索)**：
    1.  输入搜索词（带防抖）。
    2.  调用后端 API 获取新图谱数据。
    3.  **过渡动画**：旧图谱节点淡出，新图谱节点淡入。
    4.  搜索命中的节点标记为 `isAnchor`，带发光效果。

## 6. 风险与对策
| 风险 | 影响 | 对策 |
|---|---|---|
| **物理引擎不稳定** | 节点抖动或飞散 | 引入阻尼（Damping）因子，限制最大速度；设置最大边界（软边界）防止完全失控。 |
| **搜索视图切换闪烁** | 用户体验差 | 使用双缓冲（新旧数据并存淡出淡入）或节点 ID 映射平滑过渡。 |
| **后端计算 1跳邻居耗时** | 搜索响应慢 | 限制 `depth=1`，仅扩展直接邻居；使用 Redis 或内存缓存热点邻居数据。 |
