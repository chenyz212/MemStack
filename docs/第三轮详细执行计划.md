# 统一 AI 记忆桌面客户端第三轮详细执行计划（MCP 固定端口版）

## 一、目标

第三轮完成 MCP Streamable HTTP 与 stdio、只读和读写 Token、项目范围与有效期、16 个单一职责工具、正式写入和候选确认双通道，以及 Codex、Claude、Cursor、Trae、通用 MCP 的独立接入。

正式版本为 `0.4.0`。本轮不实现正式图谱、旧 SSE、OAuth、多用户、备份恢复和安装程序。

## 二、固定端口

- 桌面 REST 与 WebView2 固定监听 `127.0.0.1:18461`，使用桌面临时密钥。
- MCP Streamable HTTP 永久固定监听 `127.0.0.1:10212/mcp`，使用 Bearer Token。
- 两个端口职责完全分离；REST 不映射 MCP，MCP 不暴露 REST。
- `10212` 被占用时不随机换端口，桌面继续运行并允许用户重新检测和重启 MCP。
- `--stdio` 模式不监听端口，从 `UNIFIED_AI_MEMORY_TOKEN` 读取 Token。

## 三、Token 与 AI 助手

- Token 按 Codex、Claude、Cursor、Trae、通用 MCP 独立签发。
- 使用 Windows DPAPI CurrentUser 加密保存，允许以后重新查看和复制，明文不落盘。
- Token 默认雾化；悬停或键盘聚焦显示，移出、失焦、切换页面或按 Esc 后恢复。
- 雾化状态也能复制完整 Token。
- Token 显示名是 MCP 写入来源的唯一可信值；不接受握手、模型或工具参数覆盖。
- 支持只读、读写、项目范围、有效期、吊销和重新生成。

## 四、MCP 工具

读取工具：`memory_search`、`memory_get`、`memory_recent`、`memory_context`、`memory_related`。

正式记忆工具：`memory_create`、`memory_update`、`memory_archive`。

候选工具：`memory_candidate_submit`、`memory_candidate_list`、`memory_candidate_confirm`、`memory_candidate_reject`。

项目工具：`project_list`、`project_resolve`、`project_create`、`project_update`。

所有工具参数显式传递，不使用默认参数或模式标志。候选确认前不进入正式记忆、FTS、Embedding、最近记忆或上下文。

## 五、桌面管理

REST 提供 MCP 状态、端口检测与重启、Token 列表与密文解密查看、创建、吊销、重新生成和真实连接测试，以及候选列表、详情、确认和拒绝。

“连接 AI”页面为五类助手分别展示服务状态、权限、项目范围、有效期、最近调用、雾化 Token、复制、测试、吊销、重新生成和专属配置。所有 HTTP 配置固定使用 `http://127.0.0.1:10212/mcp`。

“记忆”页面增加待确认分类；总览增加候选数、最近 AI、最近调用时间和 MCP 端口状态。

## 六、实施与验收

依次实施数据库增量迁移、DPAPI Token、权限上下文、候选事务、16 个工具、HTTP/stdio、五类配置生成、连接 AI 页面、候选页面、自动化与真实 EXE 验收。

验收必须确认：两个端口严格隔离；端口占用不漂移；stdio 不监听端口；Token 可长期雾化查看且不明文落盘；五类配置正确；权限和来源正确；候选确认前不进入检索；第二轮数据无损升级；测试和 Release 构建通过。
